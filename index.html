Quadis Hotels

Live in production
quadishotels.com ↗ Code ↗

A booking platform for a Delhi NCR hotel group — rooms, rates, real payments and an admin back-office. Designed, built, deployed and operated end-to-end, solo, and running live on infrastructure I stood up and handed over.

React + TS SPA→nginx→Node / Express API→PostgreSQL EC2 · ap-south-1 · S3 media · Razorpay · 9 properties · 20 room types · 197 rooms
  • Shipped the whole stack alone — a React 18 + TypeScript front end on Vite, a Node/Express + TypeScript booking API, and a PostgreSQL schema covering properties, room types, rate plans, holds and bookings.
  • Owned production on AWS end-to-end, then migrated the entire stack off my account (S3 + CloudFront + Elastic Beanstalk + RDS) onto the client's own AWS account — a hardened EC2 instance in ap-south-1 with an Elastic IP, nginx, systemd and Postgres — via scripted build/push deploys and a rehearsed DNS cutover, with no data loss.
  • Integrated Razorpay checkout with webhook signature verification, PDF invoicing and WhatsApp confirmations; secrets load from SSM Parameter Store and every auth path fails closed rather than issuing forgeable sessions.
  • Hardened both box and app: TLS and security headers at nginx, rate limiting, Helmet and Zod validation on every route, and a systemd unit locked down to ProtectSystem=strict · NoNewPrivileges · MemoryMax.
  • Built Quadis Assist, an LLM concierge on Groq with a deterministic fallback, so the chat still answers guests when the model is unreachable.
